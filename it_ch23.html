① 擬似言語の読み方

この章のねらい

第22章で科目Bの全体像をつかんだ。この章は手を動かす章。IPA が公開している科目Bの実際の試験問題（令和5〜8年度）を素材に、擬似言語を1行ずつ追う練習をする。

科目Bの20問中約16問がこの形式。ここが読めれば合格の8割は手に入る。

記述形式（問題用紙の冒頭に毎回載っている）

書き方意味
○整数型: 関数名(整数型: x)関数の宣言。「整数型:」は戻り値の型
整数型: i, s ← 0変数の宣言。← は代入（右の値を左に入れる）
/* 注釈 */　// 注釈コメント。実行されない
if (条件) … elseif … else … endif上から順に評価し、最初に真になった枝だけ実行
while (条件) … endwhile前判定。条件が真の間くり返す（最初から偽なら0回）
do … while (条件)後判定。必ず1回実行してから条件を見る
for (i を 1 から n まで 1 ずつ増やす)回数の決まったくり返し。n も含む
return 値関数を終えて値を返す
繰返し処理を終了するそのループを抜ける（break）

演算子で間違えやすいもの

mod：割り算の余り。7 mod 4 ＝ 3
÷ の商：割り算の整数部分。7 ÷ 4 の商 ＝ 1
and / or：論理積・論理和。and の方が先に評価される
≠ ≦ ≧：「等しくない」「以下」「以上」。≦ は境界を含むので、ループの回数が1回変わる
未定義の値：まだ値が入っていない状態。配列の空き・リストの末尾判定に使われる
優先順位：() ＞ not ＞ 乗除・mod ＞ 加減 ＞ 比較 ＞ and ＞ or。
「(i mod 4) が 0 と等しい」のように、試験ではカッコで明示されることが多い。

配列の読み方

・data[3]：配列 data の3番目の要素
・要素番号は 1 から始まる（問題文に必ず書いてある。0始まりの問題も稀にある）
・data の要素数：中に入っている要素の個数
・{ }：配列の中身。{1, 2, 3} は要素数3
・二次元配列 m[r, c]：r 行 c 列の要素。行が先
・data の末尾に x を追加する：要素数が1増える
整数型の配列: data ← {10, 30, 20, 40} 整数型: len ← dataの要素数 // len は 4 data[len] ← 99 // data は {10, 30, 20, 99} dataの末尾 に 5 を追加する // data は {10, 30, 20, 99, 5}

for 文の「制御記述」を正確に読む

制御記述i がとる値回数
i を 1 から 5 まで 1 ずつ増やす1, 2, 3, 4, 55回
i を 2 から len まで 1 ずつ増やす（len＝9）2, 3, …, 98回
i を len から 2 まで 1 ずつ減らす（len＝9）9, 8, …, 28回
j を 8 から始めて 20 を超えない範囲で 4 ずつ増やす8, 12, 16, 204回
i を 3 から n まで 1 ずつ増やす（n＝2）（なし）0回
「増やす」か「減らす」かは、配列を前からずらすか後ろからずらすかで結果が変わる典型ポイント（③の「配列のシフト」で扱う）。

② トレースの手順

トレース表の作り方（毎回これ）

① 変数名を横に並べる（登場する変数を全部。配列は中身を書く欄を作る）
② 具体的な入力値を1つ決める（問題文に例があればそれを使う。なければ小さい値）
③ 1行ずつ実行し、値が変わった変数だけ書く
④ くり返しは1周＝1行。条件判定の真偽も書く
⑤ return の値（または出力）を選択肢と照合する
頭の中でやらない。科目Bで落ちる人の大半は「読めた気になって」トレースを省く。手で書けば5分、頭でやると3回読み直して7分かかる。

整数型: i ← 1, s ← 0 while (i ≦ 10) s ← s ＋ i i ← i ＋ 3 endwhile

例2：後判定（do～while）

例4：配列を書き換える処理は「配列の欄」を毎行書く

整数型の配列: data ← {1, 2, 3, 4, 5} 整数型: top ← data[5] for (i を 5 から 2 まで 1 ずつ減らす) data[i] ← data[i － 1] endfor data[1] ← top

③ 頻出パターン 8 選

IPA の公開問題（令和5〜8年度・各6問）から、アルゴリズム問題の型を8つに整理した。どの型かを最初に見抜くと、トレースの前に「何を追えばいいか」が決まる。

型1：配列のシフト（ずらす向き）

末尾を先頭へ・先頭を末尾へ移す処理。上書きで値を失わない向きにループを回す。後ろへずらす＝後ろから、前へずらす＝前から。②の例4が実物。

型2：2進数と補数

○8ビット型: complement(8ビット型: x) 8ビット型: y y ← x ▽ 11111111 // ▽ は排他的論理和＝全ビット反転 y ← y ＋ 00000001 return y
「x に足すと 0 になる値」＝2の補数＝全ビット反転して 1 を足す。∧（論理積）は「マスク」、∨（論理和）は「ビットを立てる」、▽（排他的論理和）は「反転」。
例：x＝00000011 → 反転 11111100 → ＋1 → 11111101。足すと 1 00000000、あふれた桁を捨てて 0。

型3：スタック（push / pop と位置変数）

大域: 整数型: stackPos ← 3 // 次に格納する位置 大域: 整数型の配列: stack ← {4, 3, 未定義, 未定義} ○論理型: push(整数型: inputData) if (stackPos ≦ stackの要素数) stack[stackPos] ← inputData stackPos ← stackPos ＋ 1 return true endif return false ○整数型: pop() 整数型: popData ← 未定義の値 if (stackPos ＞ 1) stackPos ← stackPos － 1 popData ← stack[stackPos] stack[stackPos] ← 未定義の値 endif return popData
位置変数が「次に入れる場所」なのか「最後に入れた場所」なのかを最初に確認する。この例は前者なので、push は入れてから＋1、pop は－1 してから取り出す。

型4：再帰と呼び出し順

○proc1() "A" を出力する proc3() ○proc2() proc3() "B" を出力する proc1() ○proc3() "C" を出力する
proc2 を呼ぶと：proc3→C、B、proc1→A、proc1 の中の proc3→C。答え C, B, A, C。
呼び出しが終わったら呼んだ場所の次の行に戻る。戻り先を矢印でメモしながら追う。

型5：併合（マージ）と「どの while が何回」

○整数型の配列: merge(整数型の配列: data1, 整数型の配列: data2) 整数型: i ← 1, j ← 1, k ← 1 while ((i ≦ n1) and (j ≦ n2)) if (data1[i] ≦ data2[j]) work[k] ← data1[i]; i ← i ＋ 1 else work[k] ← data2[j]; j ← j ＋ 1 endif k ← k ＋ 1 endwhile while (i ≦ n1) work[k] ← data1[i]; i←i＋1; k←k＋1 endwhile while (j ≦ n2) work[k] ← data2[j]; j←j＋1; k←k＋1 endwhile /*** α ***/ return work
比較入れた値ijwork

i＝3＞n1 → 1つ目終了2つ目 while：i≦2 偽 → 0回

merge({2,3}, {1,4}) のとき α は 1回。「残った方を流し込む」後半の while は、先に使い切った配列と反対側だけが動く。

型6：ハッシュ（衝突したら第2の関数）

○整数型: calcHash1(整数型: value) return (value mod 5) ＋ 1 ○整数型: calcHash2(整数型: value) return ((value ＋ 3) mod 5) ＋ 1 hashArray ← {5個の －1} add(3); add(18); add(11) // 空(－1)なら格納、埋まっていれば calcHash2 で再挑戦

型7：二重ループで「条件が真になった回数」

for (i を 1 から (lenData － lenKey ＋ 1) まで 1 ずつ増やす) for (j を 1 から lenKey まで 1 ずつ増やす) // α if (data[i ＋ j － 1] が key[j] と等しい) /*** β ***/ if (j が lenKey と等しい) resultの末尾 に i を追加する endif else αの行から始まる繰返し処理を終了する endif endfor endfor

④ 本番の解き方

アルゴリズム問題：4手順で固定する

手順1　冒頭の説明文で「何をする関数か」に線を引く（例：「昇順に整列する」「素数だけを返す」）
手順2　問われ方を確認：空欄補充か／実行結果か／回数か
手順3　トレース：問題文の具体例（あれば）でトレース表を書く。空欄補充なら選択肢を入れてトレースし、説明文どおりになるものを残す
手順4　照合：残った選択肢を説明文と突き合わせる。2択で迷ったら境界値（0・1・最後）で試す

実演：空欄補充（令和7年度 公開問題 問2）

説明文：関数 change は 10 より大きい整数 n を受け取り、1円玉・5円玉・10円玉でちょうど n 円にする組合せの総数を返す。例：12円は4通り。
○整数型: change(整数型: n) 整数型: count ← 0 整数型: rest ← n while ( 　　 ) count ← count ＋ (rest ÷ 5 の商) ＋ 1 rest ← rest － 10 endwhile return count 解答群　ア rest ≧ 0　イ rest ≧ 5　ウ rest ≧ 10　エ rest ＞ 0　オ rest ＞ 5　カ rest ＞ 10
手順1：組合せの総数。手順2：空欄補充。手順3：例の n＝12 で「4通り」になる条件を探す。
周rest加える数countrest（更新後）

2周目に入る条件は rest＝2 で真、rest＝－8 で偽。候補は ア（≧0） と エ（＞0）。
手順4（境界値）：n＝20 なら 10円玉2枚で「1円玉も5円玉も0枚」の1通りがあり、これは rest＝0 のときに数える。よって rest＝0 でも回る ア が正解。

セキュリティ問題（約4問）の読み方

① 設問を先に読む：「ルール3に違反しているものは」「情報システム部に依頼した対策は」など、何を選ぶかを決めてから本文へ
② 本文の該当箇所だけ照合：ルール番号・表の項番と、現在の運用を1対1で突き合わせる。他のルールの違反を混ぜない
③ 消去法：「守りを弱める選択肢」（機能の無効化・パスワード短縮・速度制限）はまず消える
④ 数字は計算する：RPO（目標復旧時点）＝障害の何時間前のデータまで戻すか／RTO（目標復旧時間）＝何時間で復旧するか。バックアップの時刻表を書いて数える
例（令和7年度 問6）：土曜2時にフル（復元4時間）、火・木2時に増分（各0.25時間）。木曜正午に全消失 → 土フル＋火増分＋木増分＝4＋0.25×2＝4.5時間。RPO 72時間・金曜正午の障害 → 火曜正午のデータまで復元が必要。ICT継続計画の承認は経営層＝CISO。
